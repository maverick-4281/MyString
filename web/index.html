Motivation

Why build a custom C++ String class?

In C++, standard std::string hides dynamic heap memory management, buffer resizing, and destructor calls. Writing MyString from scratch forces direct interaction with raw memory management using new[] and delete[].

Dynamic Memory Allocation

Strings vary in length at runtime. MyString requests memory from the heap dynamically using new char[len + 1] rather than stack arrays.

Manual Memory Cleanup

Heap allocations persist until explicitly freed. MyString::~MyString() ensures memory is deallocated via delete[] str when objects go out of scope.

Deep Copy Semantics

Default member-wise copying leads to shallow copies and double-free crashes. MyString implements explicit copy constructors for independent heap buffers.

Core C++ Principles

The Rule of Three

If a class requires a custom destructor, copy constructor, or copy assignment operator, it almost certainly requires all three to manage resources safely.

1. Copy Constructor Deep Copy

Allocates a brand new buffer for the copied object and duplicates each byte. Prevents pointer aliasing.

MyString::MyString(const MyString& other) {
    len = other.len;
    str = new char[len + 1];
    for (int i = 0; i < len; i++) {
        str[i] = other.str[i];
    }
    str[len] = '\0';
}

Why it matters: Without this, b = a causes both a.str and b.str to point to identical memory.

2. Copy Assignment Re-allocation

Frees existing allocated buffer, allocates new memory, copies data, and guards against self-assignment.

MyString& MyString::operator=(const MyString& other) {
    if (this == &other) return *this;

    char* newStr = new char[other.len + 1];
    for (int i = 0; i < other.len; i++) newStr[i] = other.str[i];
    newStr[other.len] = '\0';

    delete[] str;
    str = newStr;
    len = other.len;
    return *this;
}

Why it matters: Prevents memory leaks by releasing the old buffer before assigning the new one.

3. Destructor Resource Cleanup

Invoked automatically when object scope ends to return dynamic heap memory back to the OS.

MyString::~MyString() {
    delete[] str;
}

Why it matters: Omitting delete[] causes memory leaks for every created object.

Educational Debugging

Memory Safety: Why Manual Memory is Hard

C++ grants total control over memory, but requires strict discipline. Here are classic memory pitfalls demonstrated conceptually.

1. Shallow Copy Pitfall

Copying only the raw pointer (b.str = a.str) makes both objects own the same memory. When one object modifies data, both change; when destructors run, a double-free crash occurs.

2. Double Free Error

Calling delete[] str twice on the same memory pointer corrupts the heap allocator state and crashes the application runtime.

3. Dangling Pointers

Accessing a pointer after its pointed-to memory has been deallocated leads to undefined behavior or segmentation faults.

4. Memory Leaks

Reassigning a pointer (str = newStr) without calling delete[] str first permanently loses access to the old heap block.

5. Missing Null Terminator

Forgetting str[len] = '\0' causes functions like std::cout << str to read past buffer bounds until encountering a random zero byte in memory.

6. RAII Solution

Resource Acquisition Is Initialization: MyString acquires heap memory in constructors and releases it in destructor automatically.
