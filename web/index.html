C++ I/O Semantics

Stream Operators: operator<< & operator>>

In standard C++, stream operators allow MyString objects to seamlessly integrate with standard streams like std::cout and std::cin.

Stream Output Operator std::ostream

Streams the internal null-terminated char* str buffer directly to output streams.

std::ostream& operator<<(std::ostream& out, const MyString& s) {
    out << s.str;
    return out;
}
Stream Input Operator std::cin

Reads input into a buffer, frees existing object memory using delete[] str, and allocates new memory with new char[s.len + 1].

std::istream& operator>>(std::istream& in, MyString& s) {
    char buffer[1000];
    in >> buffer;

    delete[] s.str;   // Free existing memory
    s.len = s.getLen(buffer);
    s.str = new char[s.len + 1];
    for (int i = 0; i < s.len; i++) s.str[i] = buffer[i];
    s.str[s.len] = '\0';
    return in;
}

Educational Debugging

Memory Safety: Why Manual Memory is Hard

C++ grants total control over memory, but requires strict discipline. Here are classic memory pitfalls demonstrated conceptually.

1. Shallow Copy Pitfall

Copying only the raw pointer (b.str = a.str) makes both objects own the same memory. When one object modifies data, both change; when destructors run, a double-free crash occurs.

2. Double Free Error

Calling delete[] str twice on the same memory pointer corrupts the heap allocator state and crashes the application runtime.

3. Dangling Pointers

Accessing a pointer after its pointed-to memory has been deallocated leads to undefined behavior or segmentation faults.

4. Memory Leaks

Reassigning a pointer (str = newStr) without calling delete[] str first permanently loses access to the old heap block.

5. Missing Null Terminator

Forgetting str[len] = '\0' causes functions like std::cout << str to read past buffer bounds until encountering a random zero byte in memory.

6. RAII Solution

Resource Acquisition Is Initialization: MyString acquires heap memory in constructors and releases it in destructor automatically.
